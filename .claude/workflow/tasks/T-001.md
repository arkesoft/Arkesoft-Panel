### Veri modeli

Üç model, üç native PG enum. Ortak konvansiyon: `id` = `String @default(cuid(2))` → PG `text`
(uzunluk sınırı YOK); zaman alanları `@db.Timestamptz(3)`; tüm tablo/kolon adları snake_case.

**`Tenant` → tablo `tenant`** (platform seviyesi, `tenant_id` taşımaz — V4)

| Alan            | Tip            | Null  | Default                | @map             | Kısıt             | Gerekçe                                                    |
| --------------- | -------------- | ----- | ---------------------- | ---------------- | ----------------- | ---------------------------------------------------------- |
| `id`            | `String`       | hayır | `cuid(2)`              | `id`             | `@id`             | `text`, sınırsız → ID formatı değişirse migration gerekmez |
| `slug`          | `String`       | hayır | —                      | `slug`           | `@unique`         | alt alan adı kaynağı, küresel tekil (AC7)                  |
| `name`          | `String`       | hayır | —                      | `name`           | —                 | NOT NULL; sonradan eklemek yıkıcı                          |
| `status`        | `TenantStatus` | hayır | `pending`              | `status`         | —                 | native enum, değer eklemek additive                        |
| `planId`        | `String?`      | evet  | —                      | `plan_id`        | **FK/indeks yok** | V2: Plan v0.17.0'da FK+indeks additive eklenir             |
| `primaryDomain` | `String?`      | evet  | —                      | `primary_domain` | `@unique`         | yalnızca **özel** alan adı; NULL = alt alan adı (A-V7)     |
| `createdAt`     | `DateTime`     | hayır | `now()`                | `created_at`     | Timestamptz(3)    |                                                            |
| `updatedAt`     | `DateTime`     | hayır | `now()` + `@updatedAt` | `updated_at`     | Timestamptz(3)    | `@default(now())` bilinçli: ham SQL insert'te boş kalmasın |
| `deletedAt`     | `DateTime?`    | evet  | —                      | `deleted_at`     | Timestamptz(3)    | soft delete; tekilliği serbest BIRAKMAZ (V1)               |

**`User` → tablo `app_user`** (platform seviyesi) — `id`, `email @unique` (küçük harf normalize,
`citext` yok), `name` **NOT NULL** (Better Auth v0.0.5 zorunlu bekliyor, A-V9),
`status UserStatus @default(active)` (`emailVerified` bu alana GİRMEZ — v0.0.5 ayrı alan),
`createdAt`/`updatedAt`/`deletedAt` Tenant ile aynı.

**`TenantMembership` → tablo `tenant_membership`** (tenant'a bağlı TEK tablo)

| Alan                    | Tip          | Null      | Default         | @map        | Kısıt                          | Gerekçe                                                                    |
| ----------------------- | ------------ | --------- | --------------- | ----------- | ------------------------------ | -------------------------------------------------------------------------- |
| `id`                    | `String`     | hayır     | `cuid(2)`       | `id`        | `@id`                          | vekil PK: v0.0.14 davet akışı + AuditLog.subject tek değerli kimlik ister  |
| `tenantId`              | `String`     | **hayır** | —               | `tenant_id` | FK → `tenant.id` Cascade       | RLS hazırlığı: ad **tam olarak** `tenant_id`, tip `text`, NOT NULL         |
| `userId`                | `String`     | hayır     | —               | `user_id`   | FK → `app_user.id` Cascade     |                                                                            |
| `role`                  | `TenantRole` | hayır     | **default YOK** | `role`      | —                              | çağıran rolü açıkça seçmek zorunda; sessiz varsayılan yetki kazası yaratır |
| `createdAt`/`updatedAt` | —            | hayır     | `now()`         | —           | Timestamptz(3)                 |                                                                            |
| —                       | —            | —         | —               | —           | `@@unique([tenantId, userId])` | AC2(d)+AC5; `tenant_id` **öncü kolon** → v0.0.13 RLS predicate'i indeksli  |
| —                       | —            | —         | —               | —           | `@@index([userId])`            | PG FK'ları otomatik indekslemez; cascade + "kullanıcı hangi tenant'larda"  |

**`deletedAt` YOK — bağlayıcı karar:** soft delete yalnızca **varlık** tablolarına, saf ilişki
tablolarına uygulanmaz. Üyelik kaldırma hard delete. Gerekçe: (a) `deletedAt` + koşulsuz
`@@unique` birlikte çıkarılan üyenin yeniden davetini kalıcı engeller (v0.0.14'ü kilitler);
(b) Prisma kısmi unique indeks desteklemez, elle SQL AC6 sapma kontrolünü bozar;
(c) kaldırma geçmişi `AuditLog`'un işi (v0.0.14).

**Enum'lar** (üye adları küçük harf: DB değeri = API değeri = ROADMAP metni, eşleme katmanı doğmasın)

| Enum           | `@@map`         | Üyeler                                                                                                   |

| `TenantStatus` | `tenant_status` | `pending`, `provisioning`, `active`, `suspended` — `deleted` YOK (A-V8)                                  |
| `UserStatus`   | `user_status`   | `active`, `suspended` (V3)                                                                               |
| `TenantRole`   | `tenant_role`   | `owner`, `admin`, `staff`, `support`, `readonly` — `platform_admin` YOK (platform yetkisi, üyelik değil) |

**Yoksayılan alanlar (bilinçli, hepsi additive eklenebilir):** `siteType` (v0.1.0),
`themeId`/`themeVersion` (v0.0.10), `emailVerified`/`Session`/`Account` (v0.0.5),
`Job` (v0.0.11), `AuditLog` (v0.0.14), `Plan`/`Subscription` (v0.17.0).

**Şemanın RLS'e hazır olduğunun garantisi (mekanizma, niyet değil):**

1. **Ad değişmezi:** tenant'a bağlı her tablonun kolonu tam olarak `tenant_id`, `text`, NOT NULL.
   v0.0.13 politikası `USING (tenant_id = current_setting('app.tenant_id')::text)` — `::text`
   cast'i ID tipimizle birebir uyuşur (uuid seçilse parse riski doğardı).
2. **İndeks değişmezi:** `tenant_id` en az bir indeksin öncü kolonu → politika seq scan'e düşmez.
3. **Makine okunur taksonomi:** `src/tenancy.ts` iki `as const` dizi açar —
   `PLATFORM_LEVEL_TABLES = ['tenant','app_user']`, `TENANT_SCOPED_TABLES = ['tenant_membership']`.
   v0.0.13 şema linter'ı allowlist olarak tüketir; v0.0.3'te `migration.sql`'i okuyan test AC5'i
   bununla mekanik doğrular.
4. **Sapma güvenliği:** RLS politikaları Prisma veri modelinde temsil edilmez → v0.0.13'ün elle
   SQL'i `prisma migrate diff`'te sapma üretmez.
5. **Rol ayrımına hazırlık:** `pg.Pool` `packages/db` içinde kalır, dışa açılmaz → v0.0.13
   uygulama rolünü ve `SET LOCAL` sarmalayıcısını tek noktadan ekler.

### Bağlayıcı kararlar: R1 / R2 / R3 / R5

**R1 — Prisma generate / postinstall:** `onlyBuiltDependencies` **`[]` kalır**. Generate açık bir
turbo task'ı: `packages/db` → `"generate": "prisma generate && tsc -p tsconfig.prisma.json"`;
`turbo.json` → `"generate": { inputs: ["prisma/**"], outputs: ["generated/**","dist/generated/**"] }`
ve `build`/`typecheck`/`lint`/`test` `dependsOn` listesine `"generate"` (önek yok → aynı paket).
Kök `postinstall` **eklenmez** (install hermetik kalsın). Koşullu istisna: Prisma motor hazırlığı
install script'i gerektiriyorsa **asgari** allowlist, şu sırayla: `@prisma/engines` → `prisma` →
`@prisma/client`; blanket izin yok, her ad için Türkçe gerekçe yorumu.

**R2 — ID formatı:** **cuid2, öneksiz** (ROADMAP bağlayıcı; CLAUDE.md `tnt_01J…` örnekleri
illüstratif). Üretim **Prisma native `@default(cuid(2))`** — `@paralleldrive/cuid2` eklenmiyor.
Kolon `text`, uzunluk sınırı yok. Bilinen kısıt: `@default(cuid(2))` DDL'de değil istemcide →
**ham SQL insert `id` vermek zorunda**; kural `schema.prisma` başlığına yorum olarak girer.
Kaçış kapısı: insert öncesi ID gerekirse çağrı yerinde `id` verilir → additive, migration'sız.

**R3 — `User` tablo adı:** model `User`, tablo **`app_user`**. `user` PG'de ayrılmış kelime
(`SELECT user` rolü döner); Prisma tırnaklar ama v0.0.13'ün elle RLS/DDL SQL'i, psql hata ayıklama
ve şema linter'ı `"user"` tırnağına bağımlı hale gelir. **Konvansiyon:** ayrılmış kelimeyle çakışan
platform tablolarına `app_` öneki. v0.0.5'i kilitlemez (Better Auth Prisma adapter'ı **model adıyla**
eşler). Reddedilen: `@@map("user")`+tırnak (kırılgan), `users` (CLAUDE.md "PascalCase tekil").

**R5 — `db:reset` koruması:** `src/guard-local-database.ts` → `dist/guard-local-database.js`.
`db:reset` ve `db:push` guard'ı **önce** çalıştırır (`&&` zinciri). `db:migrate` korunmaz
(üretimde `migrate deploy` çalışmak zorunda). Mantık: (1) `DATABASE_URL`'i `new URL()` ile ayrıştır;
(2) hostname ∉ {`localhost`,`127.0.0.1`,`::1`,`postgres`} → reddet; (3) `NODE_ENV==='production'`
→ reddet; (4) kaçış kapısı `ARKESOFT_CONFIRM_DESTRUCTIVE` **hedef veritabanı adına birebir eşitse**
izin (bayrak değil ad istemesi kabuk profiline körlemesine yazılmasını engeller); (5) hata mesajı
Türkçe, **yalnızca** host + DB adı — URL ve parola asla.

`tsconfig.json`/`tsconfig.build.json` ikilisi yeni desen değil — `packages/config` aynı ayrımı
kullanıyor. Böylece `prisma.config.ts` ve `vitest.config.ts` hem tsc hem ESLint `projectService`
tarafından görülür ve `packages/config` değişmek zorunda kalmaz.

**Üretilen istemcinin yalıtımı — A yolu (birincil):** `generator client { provider = "prisma-client",
output = "../generated", runtime = "nodejs", moduleFormat = "esm" }`. `generated/` **`src` dışında**.
`generate` = `prisma generate` + `tsc -p tsconfig.prisma.json` (→ `dist/generated/` `.js`+`.d.ts`,
yalnızca hijyen bayrakları gevşek, `strict: true` korunur). `src/client.ts` bunu `package.json#imports`
üzerinden tüketir: `"#prisma": { types: "./dist/generated/client.d.ts", default: "./dist/generated/client.js" }`.
Böylece `skipLibCheck` devreye girer, **kendi src'imiz tam katılıkta kalır**.
**B yolu (yedek, tasarım yeniden açılmadan uygulanır):** generator çalışmazsa → `prisma-client-js`,

### Migration stratejisi

- **Tek migration:** `prisma migrate dev --name init`. Üretilen SQL **elle düzenlenmez** (AC6 yakalar).
- İçerik: `CREATE TYPE` (3 enum) → `CREATE TABLE` (3 tablo) → `CREATE UNIQUE INDEX`
  (slug, primary_domain, email, (tenant_id,user_id)) → `CREATE INDEX tenant_membership_user_id_idx`
  → `ALTER TABLE … FOREIGN KEY … ON DELETE CASCADE`.
- **Yıkıcı ifade yok doğrulaması:** `migration-sql.test.ts` dosyayı okur ve assert eder: `DROP ` yok,
  `SET NOT NULL` yok, `DROP COLUMN` yok, `TENANT_SCOPED_TABLES`'daki her tablo için
  `"tenant_id" TEXT NOT NULL` var. Tablo yaratımındaki NOT NULL yıkıcı değildir (mevcut veri yok).
- **Expand/contract:** ilk migration'da contract edilecek geçmiş yok; bu sürüm **kuralı kilitler** —
  sonraki her migration'da yeni kolon ya nullable ya default'lu; yeniden adlandırma = ekle → çift
  yaz → tüket → iki sürüm sonra sil; `NOT NULL`/`DROP` ayrı PR + ROADMAP işareti.
- **Elle SQL yasağı (bu sürüm):** CHECK constraint (slug deseni), trigger (`updated_at`), RLS —
  hiçbiri eklenmez. Ya sapma üretir ya gereksiz karmaşıklık.
- **Ortam ayrımı:** `migrate dev` yalnızca yerel (shadow DB yaratır). CI/üretim `migrate deploy`.
- **`db:push` tuzağı:** migration dosyası üretmez; aynı DB'de `db:push` + `db:migrate` karışımı sapma
  doğurur. `docs/development.md` kuralı: `db:push` sonrası `db:migrate`'e dönmeden önce `db:reset`.
- **AC6 doğrulaması (`db:verify`):** `prisma validate && prisma format --check && prisma migrate diff
--from-schema-datasource … --to-schema-datamodel … --exit-code`. `format --check` desteklenmiyorsa
  yedek: `prisma format && git diff --exit-code -- prisma/schema.prisma`.

- **R-A1 [orta] kapsam sınırı:** AC4'ün makine garantisi `packages/config/eslint/base.js`'e 6 satır `no-restricted-imports` girdisi gerektiriyor → PM'in "Dokunulan paketler: packages/db" ifadesinin dışına taşıyor. **Kullanıcı onayına sunuldu.** Onaylanmazsa yedek savunma (pnpm katı çözümleme + `exports` haritası + `#prisma` iç subpath) yine çalışır, ama lint'le zorlanmaz → AC4 "kontrol edildi" seviyesinde kalır.
- **R-A2 [orta] Prisma major/generator belirsizliği:** üretilen `.ts` istemcinin katı programa girmesi `noUnusedLocals`/`exactOptionalPropertyTypes` ile çakışabilir. Karşı önlem: `#prisma` dolaylaması + `tsconfig.prisma.json` (A yolu) ve tanımlı B yedek yolu.
- **R-A3 [orta] `onlyBuiltDependencies: []` ile Prisma CLI:** motor hazırlığı install script'ine bağlıysa generate/migrate patlar. Karşı önlem: asgari allowlist sırası `@prisma/engines` → `prisma` → `@prisma/client`, blanket izin yok.
- **R-A4 [orta] yeni ana bağımlılık:** `@prisma/adapter-pg` + `pg` + `@types/pg`. **Kullanıcı onayına sunuldu.**
- **R-A5 [orta] `prisma format --check` desteği:** AC6 bu bayrağı varsayıyor. Yedek: `prisma format && git diff --exit-code -- prisma/schema.prisma`.
- **R-A6 [düşük] Prettier ve üretilen kod:** `generated/` git'te olmasa da Prettier tarar. `.prettierignore` + `.gitignore`'a `packages/db/generated/` eklenmezse AC3 kırmızıya döner.
- **R-A7 [düşük] `console.*` yasağı CLI girdi noktalarında:** seed ve guard `process.stderr/stdout.write` kullanacak (gerekçe yorumuyla). Gate ajanları ihlal sanmasın.
- **R-A8 [düşük] turbo `test` önbelleği (R7):** canlı DB durumuna bağlı → `"cache": false` zorunlu, aksi halde yeşil önbellek yanlış güven verir.
- **R-A9 [düşük] Node 25 yerel / 24 hedef (R6):** `process.loadEnvFile` ve Prisma davranışı doğrulanmadı. `db` ajanı `prisma -v` ve `node -v` çıktısını raporlamalı.
- **R-A10 [düşük] `onDelete: Cascade` ve son owner:** kullanıcı hard delete'i tenant'ın son `owner` üyeliğini sessizce silebilir. İş kuralı eksiği, veri modeli hatası değil → v0.0.14/v0.20.0'da "son owner silinemez". Teknik borç olarak kaydedilecek.

- **R-A12 [düşük] `db:push`/`db:migrate` karışımı:** aynı DB'de sırayla kullanmak sapma üretir. `docs/development.md` kuralı: `db:push` sonrası `db:reset`.
