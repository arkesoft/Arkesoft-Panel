### K2 — O2 çelişkisi: **(i) yolu — her iki yüzey 403 `TENANT_MEMBERSHIP_REQUIRED`. Semver etkisi: YOK**

Ölçülmüş gerekçe: varlık oracle'ı üyelik yanıtından **önce** ve **kimlik gerektirmeden** açık — çözülemeyen host → 404 `TENANT_NOT_FOUND` (`tenant.guard.ts:57`), çözülen host + oturumsuz → 401 `UNAUTHENTICATED` (`auth.guard.ts:65`). Kimliksiz saldırgan varlığı bu ayrımdan zaten öğrenir ve bu **yapısaldır** (kiracının vitrini o host'ta herkese açık servis edilir). 403→404 **hiçbir ek bilgiyi kapatmaz**, yalnızca v0.0.5'te PR #3 CHANGELOG'uyla duyurulmuş davranışı bozar.

**§7 madde 12'nin KORUNAN yarısı:** gövde başka kiracının `id`/`slug`/`name`'ini taşımaz (bugün de doğru — `context` yalnızca log'a gider, `toErrorBody` `context`'i hiç okumaz).

**Bağlayıcı işlevsel kural (muafiyet lisansı DEĞİL):** §7 madde 12 **girdiyle kimliklenen** tenant-kapsamlı kaynaklar (ürün, sipariş, medya) için tam olarak bağlayıcı → "yok" ve "senin değil" **her ikisi de 404**. İstisna **yalnızca** "host çözümünden gelen kiracının kendisi" için.

**Karşı-olgu (kayda geçsin):** 404 seçilseydi platform **minor** olurdu (hiçbir tenant müdahale etmek zorunda kalmaz) ama duyurulmuş davranış değişimi olduğu için changeset uyarısı + CHANGELOG satırı gerekirdi. Seçilmedi: hiçbir güvenlik kazancı olmayan sözleşme kırılması.

**AC6 — NİHAİ METİN (AC tablosundaki yerine birebir geçer):** Tenant A'ya üye kullanıcının geçerli oturumuyla tenant B bağlamında `tenant.current` çağrılır. Beklenen: **HTTP 403**, gövde tam olarak `{code:'TENANT_MEMBERSHIP_REQUIRED', message:'errors.auth.tenantMembershipRequired', details:{}, requestId:'<istekteki x-request-id>'}` — v0.0.5'in HTTP yüzeyiyle **birebir aynı kod ve gövde** (test `/auth/sessions` ile `/trpc/tenant.current` çıktısını karşılaştırır). ### K3 — AC9: `AppError.publicDetails` (geçersiz kılınabilir getter, varsayılan `{}`)

Üç parça, hepsi `packages/errors`'ta, **yeni import yok** → zod-only kısıtı ihlal edilmiyor:

1. `AppError`'a `get publicDetails(): Readonly<Record<string, unknown>> { return {} }`. Alt sınıflar `override get publicDetails()` (`noImplicitOverride` → `override` **zorunlu**, yazım hatası derleme hatası).
2. `toErrorBody(error, requestId)` — **üçüncü parametre kaldırılır**; `details` tek kaynaktan gelir.
3. `resolveAppErrorDetails()` **silinir**; `ValidationError` `{fields}`, `DependencyUnavailableError` `{checks}` döndüren override'lar alır. **Davranış birebir korunur** — mevcut `error-mapping.test.ts` assert'leri **değişmeden** yeşil kalmak zorunda (refactor'ün davranış-koruyucu olduğunun kanıtı; test gevşetilmez).

Bu bir **domain hatası tanımı değil**, taban sınıfta **genişletme noktası** — `httpHeaders`'ın v0.0.5'te additive eklenmesiyle aynı sınıf karar.

**`isAppError`'ın yapısal yedek yolu için savunma (zorunlu):** yapısal eşleşmeyle `true` dönen nesnede `publicDetails` **olmayabilir** → `toErrorBody` körü körüne yazmaz, `z.record(z.string(), z.unknown()).safeParse()` başarısızsa `{}` (fail-closed). `appErrorShapeSchema` **büyütülmez**.

**AC9(b):** test dosyasında tanımlı alt sınıf `override get publicDetails(){return {probe:'x'}}` yazar; `details` **hem** HTTP (`mapErrorToResponse`→`toErrorBody`) **hem** tRPC (`errorFormatter`→`toErrorBody`) yolundan tele yansır. Düzenlenen dosya: **0**.

**AC10 ikinci parça (kopya literal yasağı):** `error-mapping.ts`'teki iki sabit gövde `packages/errors`'a **fabrika** olarak taşınır — `genericTransportErrorBody(requestId)`, `unknownErrorBody(requestId)`. İki yüzey **aynı** fonksiyonları çağırır → AC10 test değil **yapı** ile sağlanır.

**Reddedilen:** `details` üretimini `apps/api`'de bırakıp eşleme fonksiyonunu context'ten enjekte etmek — borcu kapatmaz, ikinci doğruluk kaynağı yaratır, AC9(b)'yi **kırar**.

### K4 — `/trpc` mount'u: Nest controller + `fetchRequestHandler`; `publicProcedure` gerilimi çözüldü

**`@All('trpc/*path')` Nest controller'ı, express middleware DEĞİL.** Üç gerekçe:

1. **`app.use()` tuzağı:** `NestFactory.create()` `init()`'te router hook'larını + not-found handler'ı kaydeder; sonradan `app.use('/trpc', ...)` yığının **sonuna** eklenir → istek not-found'a **önce** düşer. Raw express mount'u `/trpc`'yi görünmez kılabilir (R5'in "publicProcedure 404'e düşer" senaryosunun en sessiz hâli).
2. **K-A1 adaptör-nötrlüğü:** `adapters/express` yerine `adapters/fetch` → Web `Request`/`Response`. v0.0.5 bu köprüyü **ölçerek** kurdu (`to-web-headers.ts`, `httpAdapter.setHeader/appendHeader/reply`) — aynı desen tekrar kullanılır.
3. **O1:** controller rotası olduğu için global `APP_GUARD`'lar `/trpc/*` için **koşar** → `AuthGuard`'ın `withTenant()` üzerinden yaptığı üyelik kontrolü **aynen tekrar kullanılır**. Express mount'unda guard'lar **koşmazdı** → üyeliği tRPC'de yeniden yazmak gerekirdi → V2 ihlali. Bilinçli olarak seçilmedi.

**Pipeline (hiçbir mevcut dosyanın davranışı değişmiyor):**

```
RequestContext → TenantContext → AuthContext middleware ('*path', DOKUNULMUYOR)
→ TenantGuard    (unresolved → 404 TENANT_NOT_FOUND)
→ AuthGuard      (oturumsuz → 401 · üye değil → 403 TENANT_MEMBERSHIP_REQUIRED)
→ RateLimitGuard (yalnızca 4 auth rotasını tanır, /trpc'de anında true)
→ SameOriginGuard (controller @UseGuards)
→ TrpcController.handle → createTrpcRequestHandler(Request, ctx) → tRPC middleware/resolver
```

**İki küme (R5'in asıl sorusu):** `/trpc/*` **ne `TENANT_EXEMPT_PATHS`'te ne `AUTH_EXEMPT_PATHS`'te**. İki küme de **tam eşleşmeli** ve **fail-closed opt-out** (prefix/regex yasak) → sıfır değişiklikle "tenant zorunlu, auth muaf değil" elde edilir. Mekanik kanıt: `isTenantExemptPath('/trpc/tenant.current') === false` **ve** `isAuthExemptPath('/trpc/session.me') === false` + iki kümenin kardinalite assert'leri (12/9) **değişmeden** yeşil → "kimse bir şey açmadı" kanıtı.

**`publicProcedure` gerilimi — iki kavram ayrılır:**

- **Prosedür oluşturucunun semantiği** (sözleşme katmanı): `ctx.auth`/`ctx.tenant` daraltması **yapmayan** taban. Export edilir, diğer ikisinin kökü olur, **paket içinde hermetik** doğrulanır (anonim context ile resolver koşar) → AC1/AC11 kapsamı, DB/Redis'e dokunmaz.
- **HTTP yolunun erişilebilirliği** (taşıma katmanı): v0.0.6'da `/trpc` yüzeyinin **tamamı** kimlik + üyelik ister, çünkü **v0.0.6 hiçbir public prosedür yayınlamaz**.
- **Gerçek public yayınlama mekanizması (≥v0.1.0, şimdi tanımlanıyor):** prosedürün **tam** yolu `AUTH_EXEMPT_PATHS`'e (tenant'sızsa ayrıca `TENANT_EXEMPT_PATHS`'e) **tek tek** eklenir → açık, incelenebilir, fail-closed.
- **Bu mekanizma tek bir değişmezliğe dayanır: BATCHING KAPALI.** Batched istekte tek HTTP yolu birden fazla prosedür taşır → yol-bazlı muafiyet anlamını yitirir. İstemcide `httpLink` (asla `httpBatchLink`), sunucuda batching kapalı; seçenek adı spike'ta doğrulanamazsa controller seviyesinde fail-closed yedek (yol segmentinde `,` **veya** `batch` query parametresi → reddet).

**AC3 nerede ölçülür:** HTTP yolunda tenant'sız istek tRPC'ye **hiç ulaşmaz** (`TenantGuard` 404 verir). ROADMAP'in AC'si `tenantProcedure`'ün **kendisi** hakkında → AC3 `packages/trpc`'nin hermetik koşum hattında ölçülür (gerçek `errorFormatter` + gerçek istemci, dolayısıyla `error.data.code === 'UNAUTHORIZED'` ve `httpStatus === 401` **gerçekten** gözlenir). AC1/AC11 ile tutarlı.

#### KRİTİK BULGU — `appErrorBoundary` ölü koddu (S4 buldu, Orkestratör bağımsız doğruladı)

S4 testleri **gerçekten koşturduğu** için `tenant.current`'ın anonim context'te 401 değil **500** döndüğünü gözledi. İki bağımsız repro ile kök nedeni ölçtü:

**`@trpc/server@11.19.0`'ın `callRecursive`'i HER middleware seviyesinde kendi hatasını yakalayıp `{ok: false, error}` DÖNÜŞ DEĞERİNE çeviriyor → `next()` ASLA throw/reject etmiyor.** Dolayısıyla S3'ün `try { return await next() } catch { throw toTrpcError(...) }` deseni **hiçbir zaman tetiklenmiyordu**; `requireAuth`/`requireTenant`/port'un fırlattığı her `AppError` tRPC'nin jenerik `INTERNAL_SERVER_ERROR`'una düşüyordu. Etkilenen kriterler: **AC3, AC9(b), AC10**.

**Bu bulgu döngünün değerini kanıtlıyor:** S3'ün `lint`/`typecheck`/`build` üçü de yeşildi. Üç statik kapı da `try/catch`'in ölü kod olduğunu **göremez** — yalnızca gerçek bir çağrı yapıp dönen değeri okumak ortaya çıkarıyor. S3 test koşmamıştı çünkü test altyapısı S4'ün kapsamındaydı.

**S4'ün iki doğru davranışı:** (1) testi geçirmek için **gevşetmedi** — doğru davranışı assert eden testi yazdı ve bugün kırmızı olduğunu dosyaya yorum olarak belgeledi; (2) kendi izni dışındaki `trpc.ts`'e **dokunmadı**, bulguyu sahibine havale etti.

**S3'ün düzeltmesi (öneriyi olduğu gibi uygulamadı, iyileştirdi):**

```ts
const appErrorBoundary = t.middleware(async ({ ctx, next }) => {
  const result = await next()
  if (result.ok) return result
  if (isAppError(result.error.cause)) throw toTrpcError(result.error.cause, ctx)
  throw result.error
})
```

S4'ün `toTrpcError(result.error.cause ?? result.error, ctx)` önerisi yerine **açık `isAppError` kontrolü + "değilse olduğu gibi yeniden fırlat"**. Gerekçe: eski `toTrpcError`'un "unknown" dalı **her** sınıflandırılamayan girdiyi zorla 500'e çeviriyordu → tRPC'nin **kendi** ürettiği meşru bir `TRPCError` (ileride girdi doğrulamasıyla gelecek `BAD_REQUEST`) yanlış sınıflandırılıp 500'e düşerdi.
